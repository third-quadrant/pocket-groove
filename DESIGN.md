# Pocket Groove visual system

Native JavaFX/CSS, one Operate surface. The workspace is arranged like a DAW, not a dashboard: the pattern timeline is the largest area, tracks identify the instrument, and the step editor anchors the bottom.

## Palette

- Window `#0F1114`, transport `#15181D`, ruler/toolbar `#12151A`, lane `#1A1E24`, lane alternate `#181C21`, raised control `#20242B`.
- Text `#E8EAF0`, secondary `#8B929D`, dim `#5F6774`, hairlines `#262B33`, strong dividers `#343B46`.
- Accent `#E0A64E`; recording `#CC5C4D`; accepted input `#86B88D`; unmatched `#D27C6F`.
- Track colors: terracotta `#D07A5D`, ochre `#C7A04F`, teal `#62A38F`, steel blue `#5F8FB6`, muted mauve `#A47CAA`, olive `#83A55E`, sand `#B7A98C`; above seven tracks the palette cycles with a small hue/lightness shift.

## Type and density

- Bundled Barlow SemiBold for labels, track names, timecode and numerals; Nanum Gothic for Korean UI copy. No machine-dependent font fallback.
- 20px brand, 14px selected track, 13px track names, 10–11px metadata, 9px labels. Numbers are prominent; prose stays small and secondary.
- 52px track rows, 1px separators, 2px control radii. No generic card containers, no large soft shadows, no decorative gradients.

## Layout

- Top: transport with REC/PLAY/STOP, position `bar · beat · sixteenth`, BPM, 4/4, loop length, master, pitch and output settings. Export defaults to sample-exact WAV; MIDI remains selectable.
- Second row: a Korean hamburger file menu, undo/redo, selected track and key, track pitch, key/sound actions, add/remove track, song length (`BARS` + `+ 바`) and timeline zoom.
- Center: a single Canvas workspace with fixed track headers and a horizontally scrollable bar/beat/16th grid bounded by the project bar count. Repeated clips for repeat tracks, independent bar clips for individual tracks, drag bar selection across tracks, and per-bar context menus for repeat, delete, copy and insert-paste.
- Bottom: selected-track step sequencer with 16th cells, a velocity lane and stepped note-pitch lane. Repeat tracks show the shared pattern; individual tracks show the selected song bar. Melody tracks can also open a piano roll with a real MIDI keyboard on the left, multiple notes per step, note lengths and drag editing; the piano roll edits the same track data as the main sequence.
- Footer: operation status, project file, engine description and last keyboard input.
- At compact width the toolbar shrinks its spacing instead of clipping controls; tracks scroll vertically and the step grid may scroll horizontally.

## Interaction

- Selected track: tinted lane, raised header, colored track dot, amber edit cursor. Right-clicking the header opens the per-track Pitch Shift/Varispeed choice; the header shows `PITCH` or `VAR`.
- Hover: lane/step tints; step edges and cursor communicate the target.
- Active step: filled track color; velocity rendered as bar height in the lane underneath.
- Playhead: amber vertical line and ruler triangle driven by the native audio position.
- Key learning and file loading use the footer/input strip; unmatched keys are reported instead of failing silently.
- Real focus rings remain on standard controls. The Canvas views expose accessible text and arrow/space keyboard editing.

## Signature

The repeated **PATTERN A** clips make the loop feel like a real arrangement, while the bottom editor lets any step be changed in place and tuned into a melody. A hit briefly lights its track lane. There is no ambient animation beyond the playhead.

Implementation authority: `src/main/resources/drum.css` plus `DawStyle`, `ArrangementView`, `StepSequencerView`. Screenshots are generated by `DrumAppSmokeTest` into `target/screenshots/`.
