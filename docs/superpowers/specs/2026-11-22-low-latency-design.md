# 저지연 오디오 전환

## 승인된 방향
사용자가 앞선 분석의 권장 방향으로 진행하도록 요청했다. JavaFX 화면과 Java 프로젝트 관리는 유지하고, PortAudio와 작은 JNI/C++ 믹서로 오디오 경로를 교체한다. 설명은 Java 기초 지식으로 이해할 수 있게 작성한다.

## 접근 방식
- 선택: JavaFX → JNI 명령 큐 → 네이티브 PCM 믹서/반복 시계 → PortAudio WASAPI. 한 번 연 출력 스트림을 유지하고 매 타격은 메모리의 샘플을 섞는다.
- 비교: SourceDataLine은 추가 네이티브 개발이 적지만 Windows 장치 주기 제어와 JVM 영향에서 불리하다. AudioClip은 이미 캐시하더라도 타격마다 미디어 플레이어를 준비하는 경로라 목표에 맞지 않는다.
- ASIO는 전용 드라이버/SDK 배포 결정이 필요한 후속 선택 사항이다. 이번 첫 전환은 WASAPI Shared/Exclusive를 완성한다.

## 기능 보존과 실행
- 6패드, 기존 키 학습과 포커스 제한, WAV/AIFF/MP3 교체, 피치 ±12반음, BPM 40–240, 음량, 녹음·반복, 기존 .mdrum 저장/열기를 유지한다.
- 원본 파일은 계속 프로젝트에 저장한다. 로딩 시 실제 PCM으로 디코딩하고 메모리 제한을 검사한다.
- 64개 사전 할당 voice, 하나의 지속 출력 스트림, 출력 프레임 기준 루프와 녹음. 콜백에서는 메모리 할당, 잠금, 파일 I/O, JVM 역호출을 하지 않는다.
- 다른 프로그램과 함께 사용할 수 있는 Shared로 시작하고, 사용자에게 쉽게 표시한 출력 설정에서 Exclusive를 선택한다. 출력 장치·실제 보고 지연·끊김 횟수를 확인할 수 있게 한다. 보고 지연은 실제 타격 지연과 구분한다.
- 새 배포는 버전별 `dist/PocketGroove-<version>/`에 둔다. 현재 실행 중인 이전 빌드를 종료하거나 덮어쓰지 않는다.

## 검증
믹서를 장치 없이 테스트해 동시 발음·피치·게인·정지·큐 한도·루프 경계·템포·녹음을 확인한다. Java에서는 파일 형식/기존 저장 호환/UI를 검사한다. 실제 WASAPI 스트림과 런타임 포함 exe를 검증하되 물리 타건→DAC 실측 없이는 10ms 달성을 주장하지 않는다. 기존 exe를 비교 기준으로 보존한다.
